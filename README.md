# eSetMod 1.1.1

Minecraft **1.20.1** · **Fabric** 模组的「记录木棍」：右键把方块按顺序录进缓存，再用 `/setmod` 把缓存保存成命名记录、设置回放时长、清除并重放。

本版本起，**所有 `/setmod` 子命令都带一个「执行对象」参数**，因此可以直接在命令方块里执行，也可以用 `/execute as` 指定操作谁的数据。

- Mod ID：`esetmod`
- 物品：`esetmod:record_stick`（记录木棍）
- 语言：简体中文 / English

---

## 一、安装

| 依赖 | 版本 |
| --- | --- |
| Minecraft | 1.20.1 |
| Fabric Loader | ≥ 0.15.0 |
| Fabric API | 0.92.x（例如 0.92.6+1.20.1） |
| Java | 17+ |

1. 安装 Fabric Loader 1.20.1。
2. 把 `esetmod-1.1.1.jar` 和 **Fabric API** 一起放进 `.minecraft/mods`。
3. 启动游戏。

单人游戏如果要使用命令，请在创建世界时开启作弊，或在「对局域网开放」里允许作弊；服务器上需要 OP（权限等级 2）。

## 二、五分钟上手

```
/give @s esetmod:record_stick          # 1. 拿到记录木棍
                                        # 2. 用木棍逐个右键要记录的方块
/setmod name @s house                   # 3. 把刚记录的方块保存为 house（缓存清空）
/setmod speed @s house 200              # 4. 让 house 的整段回放持续 200 tick
/setmod start @s house                  # 5. 清除建筑 → 120 tick 后按顺序重新放置
```

想录第二条：

```
（继续右键新的方块）
/setmod name @s wall
/setmod start @s wall
```

想删掉不需要的记录：

```
/setmod clear @s wall
/setmod clear @s          # 只清空「还没保存」的缓存
```

## 三、记录木棍

- 外观、模型、贴图、堆叠上限、燃烧时间都跟原版木棍一致（`minecraft:item/stick` 贴图，堆叠 64，燃烧 100 tick）。
- 创造模式物品栏的「材料」页里也能直接拿到。
- **右键方块 = 记录这个方块**（记录的是被点的那一个方块，不是要放置的位置），保存坐标、方块状态和所在维度。
- 重复右键同一个方块不会产生第二条记录，只会刷新它的方块状态，顺序不变。
- 每个玩家缓存上限 **4096** 个方块。
- 箱子、门、按钮等会自己吃掉右键的方块，请**潜行 + 右键**记录。

## 四、命令

### 4.1 执行对象 `<targets>`

所有子命令都要先写「对谁执行」，之后才是记录名等参数。

| 写法 | 含义 |
| --- | --- |
| `@s` | 执行者自己（命令方块里没有执行者，会失败） |
| `@p` | 距离最近的玩家 |
| `@a` | 所有玩家（批量操作） |
| `Steve` | 指定玩家名 |
| `@a[distance=..10]` | 带选择器参数，例如只对 10 格内的玩家 |

必须是**玩家选择器**；`@e`、`@r` 之类不能用于记录类命令（`@r` 不是玩家选择器）。

> 从命令方块执行时，建议用 `@p`（最近的玩家）或直接写玩家名；`@a` 会同时操作所有在线玩家自己的记录。

### 4.2 `/setmod name <targets> <name>`

把目标玩家**当前缓存**里的方块保存成名为 `<name>` 的记录，**保存后缓存立刻清空**，之后再右键就是新的一批方块。

- 名称只能用字母、数字、`_`、`-`，长度 1–32（不支持空格和中文）。
- 每个玩家最多 **64** 条命名记录。
- 用同一个名字再保存一次会**覆盖**该记录的方块，但它之前用 `speed` 设过的回放时长会保留。
- 缓存为空时不会创建记录，会提示 «Nothing to save»。

```
/setmod name @s house
/setmod name @p tower
/setmod name Steve bridge
```

### 4.3 `/setmod start <targets> <name>`

播放某条命名记录：

1. **清除**这条记录里所有「仍然是记录时状态」的方块（你后来手动改过的方块会跳过，不会被误删）；
2. 等 **120 tick（6 秒）**；
3. 从第一个方块开始，严格按**记录时的点击顺序**逐 tick 执行 setblock；
4. **回放结束后不清除任何方块**，放好的方块会一直留着。

同一条记录重复执行会取消上一次播放并重新开始。

```
/setmod start @s house
/setmod start @p house
/setmod start @a house        # 所有玩家各自播放自己的 house
```

### 4.4 `/setmod speed <targets> <name> [ticks]`

- 不带 `ticks`：显示这条记录当前的动画时长。
- 带 `ticks`：设置这条记录**整段动画**的总时长，范围 **1–72000** tick。
- 没设置过时默认 **1 tick / 方块**，且不少于 20 tick（3 个方块也是 20 tick）。
- 方块数多于 tick 数时，每个 tick 会放多个方块；反之会隔几个 tick 放一个。
- 该记录正在回放时修改，新时长从下一次 `start` 生效。

```
/setmod speed @s house          # 查询
/setmod speed @s house 100      # 100 tick 内放完
/setmod speed @a house 1        # 瞬间放完
```

### 4.5 `/setmod clear <targets> [name]`

- 带 `<name>`：删除这条命名记录，并取消它正在进行的回放。
- 不带 `<name>`：只清除目标玩家**缓存里还没保存**的方块，命名记录不受影响。

```
/setmod clear @s house     # 删掉 house 这条记录
/setmod clear @s           # 只清缓存，已保存的记录还在
```

### 4.6 对话（不带子命令）

`/setmod` 会输出一行命令速查。

## 五、命令方块里怎么用

命令方块默认拥有权限等级 2，可以直接执行这些命令。

| 场景 | 命令方块设置 | 命令 |
| --- | --- | --- |
| 按钮触发一次回放（最近玩家） | 脉冲 / 需要红石 | `setmod start @p house` |
| 循环执行，持续检查 | 循环 / 保持开启 | `setmod clear @p`（示例：反复清缓存） |
| 区域触发，只影响附近玩家 | 脉冲 / 需要红石 | `setmod start @a[distance=..8] house` |
| 先保存再播放 | 两个命令方块串联 | ① `setmod name @p shot` ② `setmod start @p shot` |

提示：

- 命令方块没有「执行者」，所以 `@s` 在命令方块里会报 “No player was found”，请改用 `@p`、`@a` 或玩家名。
- 命令方块自身的输出不会显示给玩家，但**目标玩家会在聊天栏收到结果提示**（保存成功、开始回放、删除记录等）。
- 回放过程中的「开始 / 完成」提示显示在玩家动作栏上方。

## 七、常见问题

**Q：提示 “Unknown or incomplete command”？**
A：检查是否漏了执行对象。正确写法是 `/setmod start @s house`，不是 `/setmod start house`。

**Q：命令没反应 / 提示没有权限？**
A：单人世界需要开启作弊；服务器需要 OP，或者用命令方块执行（命令方块默认就有权限等级 2）。

**Q：命令方块里 `@s` 不能用？**
A：命令方块没有执行者实体，`@s` 解析不到玩家。用 `@p`、`@a` 或玩家名。

**Q：回放把我的建筑拆了？**
A：`start` 的第一步就是清除这条记录里的方块，这是设计行为。回放结束后方块会重新长回来；如果你在记录之后手动改过某些方块，那些方块会被跳过、不会被清除。

**Q：名字可以用中文或空格吗？**
A：不可以。名称走 Brigadier 的 `word()` 参数，只接受字母、数字、`_`、`-`。建议用 `house`、`wall2`、`bridge_north` 这类名字。

**Q：多人服务器上会不会互相干扰？**
A：不会。缓存和命名记录都是**按玩家 UUID** 分开存的；`start @a house` 会让每个玩家各自播放自己的 `house`。

**Q：回放结束后方块为什么还在？**
A：这是需求行为——只有 `start` 开始时清除，播放完成不再清除。

**Q：数据存在哪？换存档会丢吗？**
A：存在世界存档的 `data/esetmod.dat` 里（每个玩家一份）。换世界/换存档就看不到了，备份世界时这个文件会一起备份。

**Q：从 1.1.0 升级会丢记录吗？**
A：不会，存档格式向后兼容，旧数据会被正常读取。
